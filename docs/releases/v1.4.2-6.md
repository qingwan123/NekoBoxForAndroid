节点测速改为 Clash 那样的实现：**一次启动内核、并发测速、结果逐条回显**。

## 背景

升级到 1.15 内核后，节点测速明显变慢，看起来像「一个一个在测」。

原因是旧实现在测每个节点时都会**单独启动一次 sing-box 实例**（构建配置 → 初始化 → 启动
→ 测 → 销毁）。1.15 的单次启动比 1.14 更重，节点一多，启动开销就盖过了测速本身。

## 改动

- 内核新增按 outbound tag 测单个节点的接口（`UrlTestTag`）：整组节点只构建一次配置、
  只启动一次内核，各节点按 tag 并发拨号
- App 侧用协程 + 信号量控制并发，**每测完一个立刻刷新弹窗那一行**，保持原来的流式体验
- 单节点测速超时 5s → 3s，失败节点不再干等
- 批量路径异常时自动退回旧的逐节点实现

## 效果

原来 50 个节点 ≈ 50 次内核启动；现在 1 次启动 + 并发拨号。实测明显加快，
弹窗仍然是逐条出现。

## 安装

仅 arm64-v8a，release 构建（R8），签名与之前版本一致，可直接覆盖安装。
