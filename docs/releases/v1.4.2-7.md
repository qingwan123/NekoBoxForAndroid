修复 VLESS 后量子加密节点的完整可用性，并补上分享崩溃。

## VLESS Encryption + Vision（关键修复）

同时使用 `security=reality` + `flow=xtls-rprx-vision` + `encryption=mlkem768x25519plus...`
的节点此前无法连接，报：

```
initialize vision: vision: not a valid supported TLS connection: *encryption.CommonConn
```

sing-vmess 的 Vision 需要通过一张私有注册表找到它下面的 TLS 连接，而该表只认
`crypto/tls` 和 `utls`，加密层包装后的连接被拒绝。已补上 `lx_vision.go`：把
`*encryption.CommonConn` 也注册进去，并暴露它底下的连接 —— 这就是 Xray 对这种组合的做法。

已在真机网络上端到端验证：`https://www.google.com/generate_204 -> 204`。

## 订阅导入时补住加密参数

节点详情里的「VLESS 加密层」在部分情况下会留空，导致节点带着空加密去连接服务端（表现为
全部超时）。现在解析出口加了两层兜底：先取解析出的 query 参数，再退回从原始链接直接截取
`encryption=`。同时打印一行日志，便于定位：

```
vless parse: isVLESS=… queryParameter(encryption)=… bean.vlessEncryption=…
```

## 分享节点崩溃

```
Attempt to invoke interface method 'int java.lang.CharSequence.length()' on a null object reference
```

分享链接拼接时对可空的加密字段直接调用了 `takeIf`，凡是没填加密层的节点分享必崩。已修。
