修复订阅导入后「VLESS 加密层为空、节点全部超时」的根因。

## 根因

NekoBox 请求订阅时带的 UA 是：

```
NekoBox/Android/<版本> (Prefer ClashMeta Format)
```

机场看到这串，会按 **Clash YAML** 返回配置，而不是标准的 base64 节点链接。这份 YAML 里其实
**带着**加密参数：

```yaml
- { name: '新加坡|三网', type: vless, server: aysg-32.nasajiuai.help, port: 443,
    uuid: …, flow: xtls-rprx-vision, tls: true, …,
    encryption: mlkem768x25519plus.native.0rtt.…, reality-opts: { … } }
```

但 Clash YAML 解析器只读了 `flow` / `reality-opts` / `packet-encoding`，**没有读 `encryption`** ——
于是节点入库时加密层是空的，连接服务端自然全部超时。手动把密钥粘进去就能用，正好反证了这一点。

## 修复

Clash YAML 解析器的 vless 分支补上 `encryption` 字段解析，写入节点的加密层。

## 顺带说明

这就是「同一个订阅在 v2rayNG 里正常、复制到 NekoBox 也能用」的原因：v2rayNG 用的 UA 拿到的是
base64 链接（链接里 `encryption=` 就在 query 中，NekoBox 的链接解析器一直是对的），只有
Clash 格式这条路漏了字段。

## 安装

仅 arm64-v8a，release 构建，签名与之前版本一致，可直接覆盖安装。

装好后**更新一次订阅**，节点详情里的「VLESS 加密层」应该有值了。
